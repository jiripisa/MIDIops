# MIDIops v1 — Plan 4: Arp mode

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the scale-aware monophonic arpeggiator: a pure note→chord→arpeggio generator, a clock-driven `ArpEngine` with the PoC-style FIFO/loop behaviour, and an `ArpMode` with two parameter screens plus the reused worms/notes visualisers.

**Architecture:** A minimal portable `Scale` (type+root) sourced from `AppServices`. A **pure generator** `(root, Scale, params) → ordered note list` (unit-tested, no time). An `ArpEngine` (ms-driven `tick`, fake-clock testable) that schedules the generated steps to `MidiOutput` with Gate/Swing/Velocity-mode and runs the FIFO queue + loop-while-held + cycle-quantized switching + Latch + transport. An `ArpMode` owns the engine + a `NoteWormModel` (outgoing-note visualisation, reusing `WormsRenderer`/`NotationRenderer`) + the 8 params across two param screens. `ChordEngine` is left untouched.

**Tech Stack:** C++17, PlatformIO (envs `teensy41`, `native`, `test`), Unity, SDL2/RtMidi (sim), ILI9341_t3n (firmware).

Spec: `docs/specs/2026-06-06-arp-mode-design.md`. Builds on Plan 2 (`NoteWormModel`, `WormsRenderer`, `AppServices`) and Plan 3 (`NotationRenderer`). MIDI API confirmed: `core::MidiType::{NoteOn=0x90,NoteOff=0x80}`, `MidiMessage{type,channel,data1,data2}`, `MidiOutput::{sendNoteOn(ch,note,vel),sendNoteOff(ch,note),setClockBpm}`.

```cpp
#pragma once

#include <cstdint>

namespace core {

class Scale {
public:
    enum class Type : uint8_t {
        Major = 0, Minor, Aug, Dim, PentaMajor, PentaMinor, kCount
    };

    Scale() = default;
    Scale(Type type, uint8_t root) : type_(type), root_(root % 12) {}

    Type    type() const { return type_; }
    uint8_t root() const { return root_; }      // 0..11 (pitch class)
    void setType(Type t) { type_ = t; }
    void setRoot(uint8_t pc) { root_ = pc % 12; }

    // True if MIDI `note`'s pitch class is in the scale.
    bool contains(uint8_t note) const;

    // Nearest in-scale MIDI note to `note` (ties round down).
    uint8_t quantize(uint8_t note) const;

    // The MIDI note `degrees` scale-steps above `fromNote` (which is assumed
    // in-scale; if not, it is quantized first). degrees may exceed the scale
    // length — it wraps through octaves. degrees=0 returns fromNote (quantized).
    uint8_t degreeNote(uint8_t fromNote, int degrees) const;

private:
    // Returns the count + pointer to the interval table (semitone offsets
    // from root within one octave) for the current type.
    int intervals(const uint8_t** out) const;

    Type    type_ = Type::Major;
    uint8_t root_ = 0;   // C
};

} // namespace core
```

```cpp
#pragma once

#include <cstdint>

namespace core {

enum class ArpDirection : uint8_t { Up = 0, Down, UpDown, DownUp, Random, kCount };
enum class ArpRate : uint8_t { Quarter = 0, Eighth, EighthT, Sixteenth, SixteenthT, ThirtySecond, kCount };
enum class ArpVelocityMode : uint8_t { Fixed = 0, FollowInput, Accent, kCount };

// MIDI clock ticks (24 PPQN) per arpeggio step for each rate.
inline int arpRateTicks(ArpRate r) {
    switch (r) {
        case ArpRate::Quarter:      return 24;
        case ArpRate::Eighth:       return 12;
        case ArpRate::EighthT:      return 8;
        case ArpRate::Sixteenth:    return 6;
        case ArpRate::SixteenthT:   return 4;
        case ArpRate::ThirtySecond: return 3;
        default:                    return 6;
    }
}

struct ArpParams {
    uint8_t         steps        = 3;     // 1..16
    ArpRate         rate         = ArpRate::Sixteenth;
    uint8_t         gatePercent  = 80;    // 10..100
    ArpDirection    direction    = ArpDirection::Up;
    int8_t          octave       = 0;     // -2..+2
    uint8_t         swingPercent = 50;    // 50..75
    ArpVelocityMode velocityMode = ArpVelocityMode::Fixed;
    uint8_t         fixedVelocity = 100;  // 1..127 (used when mode == Fixed)
    bool            latch        = false;
};

} // namespace core
```

### Task 5: `ArpEngine` — FIFO queue, loop-while-held, latch, transport

**Files:** Modify `core/ArpEngine.{h,cpp}`; Test `test/test_arp/test_arp.cpp`.

Generalise the single active note into the queue model from spec §3.

- [ ] **Step 1: Add the queue + held tracking** to `ArpEngine`:
  - A FIFO `QueueEntry { uint8_t note; uint8_t velocity; bool held; }` ring (cap 16). `noteOn` appends (and if nothing active, promotes immediately to active + starts step 0 at `nowMs`). `noteOff(note)` marks the matching entry `held=false` (active or queued).
  - **Loop-while-held:** when the active note's sequence wraps past the end, if the active entry is still `held` (or Latch on) → loop (continue). If the active entry is `!held` (released) → finish the current cycle, then **dequeue** and promote the next entry; if the queue is empty, go idle.
  - **Cycle boundary:** "released note stops after the current cycle" — detect end-of-cycle (stepIdx wrapped to 0) and only then advance/stop.
  - **Latch on:** `noteOff` is ignored for stopping (entries stay effectively held); a new `noteOn` REPLACES the active note at the next cycle boundary (clear queue, set pending-replacement), since releases can't advance the FIFO under latch.
  - `stop()`: send NoteOff for any sounding note, clear queue + active. `reset()`: `stepIdx_=0`.
- [ ] **Step 2–4: TDD** (fake clock + event-recording FakeMidiOutput):
  - FIFO order: `noteOn(60)` then `noteOff(60)` immediately (staccato), then `noteOn(62)` staccato — at bpm/rate the engine plays 60's full cycle (3 steps) then 62's full cycle. Assert the emitted note set ordering.
  - Loop-while-held: `noteOn(60)` held (no note-off); after 2 full cycles the notes still come from 60's triad (it loops). 
  - Cycle-quantized release: hold 60, release mid-cycle (`noteOff(60)` at step 1); engine keeps playing until stepIdx wraps to 0, THEN goes idle (or to next queued). Assert the extra steps after release complete the cycle.
  - Queue-then-switch: hold 60 (looping), enqueue 62 (still holding 60) → 62 waits; release 60 → after the cycle, 62 becomes active.
  - Latch: latch=true, `noteOn(60)`, `noteOff(60)` → still loops 60; `noteOn(64)` → at next cycle boundary switches to 64.
  - `stop()` emits note-offs and goes idle; `reset()` returns to step 0.
